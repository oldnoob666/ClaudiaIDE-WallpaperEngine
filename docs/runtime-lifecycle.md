# 编辑区资源生命周期

## 3.1.52.17：排除灯泡菜单的临时预览

WPF 弹出菜单中的预览编辑器可能通过逻辑树继承主窗口，但其视觉元素不属于壁纸覆盖的主窗口根面板。此前只按 `Window.GetWindow` 选择编辑器，会先清除这种预览的背景，随后又因它位于视觉树外而恢复背景；两次背景变化不断触发 DataBind 刷新，使较低优先级的输入和绘制无法执行。

透明处理现在先检查编辑器是否位于壁纸根面板的视觉树内。弹出预览保留原有背景；从覆盖区域移出的已跟踪编辑器由原有清理逻辑恢复，不再重复清除。停靠编辑器仍在 Render 前及时透明化。

`LifecycleProbe <输出目录> --lightbulb` 使用真实 WPF Popup 和调度器验证窗口归属与视觉树范围不同的情况，检查 Input 操作能否执行，并覆盖编辑器移入弹窗后的背景恢复。旧实现会被一秒看门狗判定为输入饥饿，修复后五项检查通过。

## 3.1.52.16：切换脚本时及时透明化

共享主窗口背景现在监听文本视图的显示、加载、获得焦点和背景画刷变化事件，将透明化更新合并到下一次 Render 之前的 DataBind 调度。该路径只更新画刷，不创建、销毁或移动视觉子元素；播放器和视觉树的生命周期继续在 Background 调度中处理，保留原有防崩溃逻辑。

每秒轮询继续作为兜底。已透明的编辑区不重复写入背景属性，避免背景变化事件反复排队；关闭视图时解除事件订阅，关闭或禁用共享背景时取消待处理更新。首帧前继续保留主题底色，关闭功能仍还原画刷、绑定及鼠标命中行为。

`LifecycleProbe --ide` 在停用每秒轮询后，直接检查标签切换、背景重置、焦点切换和新建编辑区的第一帧，防止周期刷新掩盖短暂黑屏。

## 标签切换保留与 60 秒休眠

独立编辑区播放器只在首次可见时创建。切换脚本后，隐藏标签及临时卸载的开放视图保留播放器和动画状态，停止该视图的布局及诊断轮询；网页不主动暂停保留期内的视频和场景。后台帧率仍受 WebView2 调度影响，不能保证与可见标签一致。

同一 VS UI 调度器上的编辑区共用一个 60 秒倒计时。切换到另一脚本或切换分屏中的脚本焦点时重新计时；回到同一脚本的焦点、打字、滚动、布局及设置刷新不重置倒计时。超时后只释放隐藏标签，分屏中所有可见编辑区继续播放。休眠不显示提示，不修改设置；再次切到已释放的标签时，重新创建播放器并开始新的保留期。

关闭视图、最小化或隐藏所属窗口、禁用背景、透明度为零及切换到共享主窗口背景时仍及时释放。所有视觉层移除继续在 WPF 当前属性遍历结束后执行；旧播放器的异步回调继续核对实例身份。关闭最后一个编辑区时停止共用休眠计时器。

开启「工具窗口背景透明」时，主窗口停靠区已经共用一个播放器，无需按标签缓存；浮动编辑器的独立播放器使用上述休眠策略。

## 3.1.52.12：修复标签切换崩溃

3.1.52.10 在 IsVisibleChanged 回调中同步移除背景层。VS 的编辑器根面板还有位于文本视图之后的滚动条等兄弟控件；WPF 正在按原有子元素数量传播可见性时，移除较早的子元素会使遍历索引越界，导致 Grid.GetVisualChild / InvalidateForceInheritPropertyOnChildren 未处理异常并退出 VS。

生命周期事件和布局/设置更新现在仅排队，合并到 Dispatcher 的下一次 Background 调度中执行创建、移除及销毁。先等待当前属性遍历退出，再读取最终可见状态；不依赖一秒轮询。卸载时立即使旧异步回调失效；关闭视图也延后移除背景层，避免在树拆卸过程中重入。

切换到普通图片时，先等待延迟清理及旧画刷还原完成，再应用替换模式的样式；如果等待期间设置再次变化，重新按当前模式分派，并避免旧操作清空新的播放器引用。

回归测试增加文本区后方的兄弟滚动条：旧版稳定复现与用户 Windows 崩溃日志相同的索引越界。修复后继续验证多次切换和同一轮调度中的可见性合并，保留隐藏播放器释放与首帧遮蔽功能。

## 原因与改动

最早的实现在每个视图创建时立即构造并初始化 WebView2；隐藏标签仅通过每秒脚本调用暂停，浏览器、页面和场景纹理继续保留。3.1.52.12 改为根据可见性释放播放器；现在进一步改为上述 60 秒延迟释放策略，兼顾短期切换与长期占用。

每个可见编辑区独立播放，分屏中不要求键盘焦点。休眠释放隐藏标签、最小化、禁用背景或透明度为零时，在当前 WPF 属性遍历结束后的调度中销毁 WebView2、移除背景层并恢复编辑器/边栏画刷。短期切回直接复用，释放后切回则重新创建页面、读取当前选择，播放进度重新开始。同一 VS 进程仍共享 WebView2 环境和缓存；释放播放器不表示共享浏览器进程立即退出或系统内存立刻归零。

初始化任务在等待共享环境和原生控制器之后，都会核对播放器身份；快速切换时旧任务无法重新挂回视图。已销毁页面的首帧回调也会被忽略。

## 首次加载与闪白

旧版在 EnsureCoreWebView2Async 完成后才设置透明背景，而且页面透明度要等首次定时更新。初始化阶段存在白色默认背景及透明度尚未生效的窗口；HTML 同步加载 WebWallGL 也会阻塞视频页面读取壁纸状态。

新版在控件插入视图及原生控制器创建前设置透明背景，并用普通 WPF 容器保持零透明度。等待期间保持原编辑器主题画刷。视频通过 requestVideoFrameCallback（旧运行时回退为两个动画帧）确认首帧，场景使用 WebWallGL 的首个渲染帧回调；之后才接入完整背景层并应用当前透明度。后续布局继续复用原有固定位置及行号栏覆盖逻辑。

页面先读取状态，仅场景按需异步加载 WebWallGL，视频不加载该脚本。共享浏览器环境不反复初始化，移除常规的每秒透明度/暂停脚本调用。冷启动仍包括 WebView2 控制器创建、素材读取、解码或场景渲染；这些成本无法完全消除。日志新增 controller 和 First frame 耗时，可用于区分浏览器初始化与素材等待。

## 验证

3.1.52.14 的「工具窗口背景透明」默认关闭。开启时，主窗口停靠区域改用一个共享播放器，主窗口中的文档播放器释放；浮动编辑器保留独立播放器。输出等没有 Document 角色的文本视图由额外的视图监听器登记，统一透明化其公开背景属性。关闭开关后恢复工具窗口画刷、绑定与动态资源表达式，并恢复文档播放器。共享播放器也在隐藏/最小化时释放，首帧前不透明化工具窗格。

`tests/ToolWindowProbe` 覆盖画刷、绑定、动态主题资源、选中高亮、新增/移除控件及重复切换。`LifecycleProbe` 追加 `--ide` 时验证真实 WebView2 共享播放器，包括没有打开文档、避免重复播放器、隐藏、最小化、切回编辑区模式和快速开关。

常规自动检查：

```powershell
dotnet run --project tests/WallpaperEngine.Tests
node --test tests/Player.Tests/player.test.cjs
MSBuild.exe tests/ViewportProbe/ViewportProbe.csproj /restore /p:Configuration=Release /v:minimal /nologo
& tests/ViewportProbe/bin/Release/net472/ViewportProbe.exe
```

生命周期探针需要 Windows、WebView2 和本机可播放的真实场景/视频，运行生产 WallpaperBackground 和 WallpaperSurface，通过 IWpfTextView 代理提供编辑器几何；不是完整 VS 自动化。它只读给定素材，在输出目录写独立配置，不改变 Wallpaper Engine 的选择。Node.js 仅用于开发测试，不是插件运行依赖。

```powershell
MSBuild.exe tests/LifecycleProbe/LifecycleProbe.csproj /restore /p:Configuration=Release /v:minimal /nologo
& tests/LifecycleProbe/bin/Release/net472/LifecycleProbe.exe '<输出目录>' '<场景的完整入口路径>' '<视频的完整入口路径>'
```

结果在输出目录的 lifecycle.log。可追加 --inspect，让场景和视频各停留 20 秒供人工观察。探针覆盖隐藏初始不分配、初始化中隐藏保留、快速返回复用、隐藏视频继续推进、首帧前遮蔽、全局倒计时重置、真实 60 秒超时、休眠后的原生销毁与恢复、可见分屏、隐藏命令、最小化、卸载重载及最终关闭。倒计时检查需要约 95 秒。ViewportProbe 覆盖滚动位置、边栏、输入和画刷还原；播放器脚本测试覆盖按需加载、隐藏动画及过期回调。
