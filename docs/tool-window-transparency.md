# 工具窗口透明：实现与验证

初始版本：3.1.52.14；验证日期：2026-10-18。当前正式版 [3.1.52.17](https://github.com/oldnoob666/ClaudiaIDE-WallpaperEngine/releases/tag/v3.1.52.17)修复了展开灯泡菜单时的界面卡死，并保留代码鼠标操作修复和切换脚本时的及时透明化，详见[生命周期说明](runtime-lifecycle.md)。文末保留首次预发布时的历史验证记录。

## 使用

启用 Wallpaper Engine 背景后，在「扩展 → ClaudiaIDE → 打开设置」的浅色/深色主题页，将「工具窗口背景透明」设为 True。设置按所选背景主题保存，默认 False。关闭后恢复原有工具窗口外观和编辑区独立播放，无需重启。

主窗口停靠区域共用一个 WebView2 composition 播放器。工具窗口背景使用可恢复的属性覆盖；绑定和动态资源表达式在关闭时恢复。普通树节点与列表行透明，选中/悬停行保留高亮；选中展开父节点不会使其普通子节点重新变成不透明。工具栏、按钮、输入控件和标签高亮保留。

背景首帧就绪前保留主题背景。隐藏背景、透明度为零或最小化窗口时释放播放器，恢复后重新创建。浮动编辑器继续使用原有独立播放器。独立浮动工具窗口、原生 HWND 和第三方自绘窗口不保证透明。

## 真实 VS 验证

在同一套 VS 2022 的独立 `/RootSuffix Transparency` 配置中验证。普通 VS 配置未替换。

- 应用 Wallpaper Engine 当前场景壁纸后开启开关：代码区、输出栏、错误列表和解决方案资源管理器共用连续背景。
- 在 VS 中成功生成测试解决方案，输出文本可读；日志确认 BuildOutput 文本视图经 MEF 监听器登记。
- 展开解决方案节点后，普通文件行继续透出壁纸，选中行保留高亮。
- 从资源管理器打开另一个代码文件，仍使用共享背景。
- 重启实验 VS 后开关保持开启。
- 在选项页关闭开关后，资源管理器及错误列表恢复不透明背景，编辑区动态壁纸继续播放。
- 最终验证期间没有发现新的相关 devenv 或探针 Application 1000/1026 崩溃事件。

验证使用本机已有素材；未改变 Wallpaper Engine 的壁纸选择。测试发布标签为 `v3.1.52.14-preview.1`，标记为 Pre-release；VSIX 内部版本为 `3.1.52.14`。稳定版 `v3.1.52.13` 及 `main` 分支保留，测试源码使用 `codex/tool-window-transparency` 分支。
