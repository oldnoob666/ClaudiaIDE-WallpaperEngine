# dsh-wallpaper-engine 实现拆解

参考：[elysia395/dsh-wallpaper-engine](https://github.com/elysia395/dsh-wallpaper-engine/tree/01fbb8b8e66fd7e405e9c878d18dbd456187f111)，提交 `01fbb8b8e66fd7e405e9c878d18dbd456187f111`。这是开源源码分析。

| 文件 | 作用 | 本次借鉴 |
| --- | --- | --- |
| `lib/steam-discovery.js` | 找 Steam 和 libraryfolders.vdf 中的库 | 自动定位安装路径 |
| `lib/wallpaper-scan.js` | 枚举 431960 工坊项目、解析 project.json | 读取当前项目类型、入口和标题 |
| `lib/inventory.js` | 素材清单和播放列表 | 本次只取桌面当前项目 |
| `lib/media-origin.js` | 本机 HTTP 素材服务 | 127.0.0.1 素材服务和视频 Range |
| `src/video-layer.js` | HTML video 播放 | 编辑区 WebView2 视频播放 |
| `lib/webwallgl/renderer.js` | WebWallGL.createScene / httpSource | 在文字下方实时渲染场景 |

核心是使用 Wallpaper Engine 已下载的素材，视频交给浏览器，场景交给 [WebWallGL](https://github.com/oneincase/webwallgl) 重建渲染，无需嵌入 Wallpaper Engine 原生窗口。

共享素材不等于跟随桌面选择，也不等于进度同步。DSH 的素材库/播放列表并未直接解决 VS 的实时跟随，因此本次另外增加官方 `getWallpaper` 查询。

```text
官方 getWallpaper 查询（WE 未运行时读已保存的 config.json）
  → WallpaperProject：project.json / 实际入口文件
  → WallpaperHost：限定项目目录的 127.0.0.1 素材服务
  → WebView2CompositionControl：HTML video / WebWallGL 3.0.0
  → ClaudiaIDE 编辑区背景层：代码文字位于上方
```

保留原模式编号、设置入口、透明度和隐藏命令，新增 `WallpaperEngine=6` 与“跟随 Wallpaper Engine”菜单。补齐新模式启动时的 provider 映射，切换背景时清理旧图，视频 URL 保留子目录。

素材服务拒绝越界、绝对路径、ADS 和重解析点，状态接口要求自定义请求头，壁纸内容与管理接口隔离。不执行 application 壁纸。播放器和 WebWallGL MIT 许可证随包分发，不使用远程脚本。

实测发现：WE 2.8.42 不立即保存切换后的配置；官方查询直接写控制台，需隐藏控制台工具捕获；scene.json 声明可能实际只存在 scene.pkg；CLI 中文文件名损坏时可用 project.json 的原始入口。真实场景和视频已通过，其他场景兼容性取决于具体素材。

ClaudiaIDE 基线：[Release3.1.52](https://github.com/buchizo/ClaudiaIDE/tree/23d555d0a817c3deee34961bff18412c9e26b5b0)。渲染器固定为 npm WebWallGL 3.0.0，许可证保留在 VSIX 的 `WallpaperEngine/WebWallGL-LICENSE.txt`。
