# 3.1.52.15：修复透明模式下的代码鼠标命中

3.1.52.14 Preview 1 在开启工具窗口透明后，部分编辑器的点击和拖选会被装饰层拦截。键盘仍能移动光标。

## 根因与修复

工具窗口背景遍历把 `Background == null` 的编辑器装饰 Canvas 也设置成了 `Brushes.Transparent`。这两种状态虽然视觉上都没有底色，WPF 中的鼠标命中行为却不同：null 背景的空白区域不参与命中，透明画刷会让整个 Canvas 成为命中表面。因此，文本上方原本只绘制装饰的空白层挡住了鼠标。

只将已经存在的画刷改为透明，保留 null 背景。保留装饰层本身的命中能力，使其中的真实交互元素仍可使用；不全局禁用编辑器或装饰层输入。其他背景恢复和播放器生命周期逻辑不变。

## 回归验证

`ToolWindowProbe.CheckEditorMouseHit` 在真实 WPF Window 中把 null 背景的 Canvas 放到 TextBox 上方，完成渲染后执行 `InputHitTest`。测试覆盖启用前、启用后、周期刷新后、关闭后的鼠标目标，以及装饰 Canvas 的 null 背景保持。

旧代码稳定失败：启用后命中 Canvas。修复后命中 TextBoxView。之前的检查只验证了外观与 `IsHitTestVisible` 属性，未检查实际命中结果，因此漏掉了这一回退；本次补上实际命中断言。

修复后通过 214 项自动检查。日常 VS 已安装同一份 3.1.52.15 构建并核对 DLL 哈希。在透明壁纸显示期间，实际鼠标点击将光标从第 4 行移动到第 12 行；双击选中 `Line010` 标识符；拖动选中了第 12 至 14 行的代码，未修改测试文件内容。此前的 3.1.52.14 中，同位置点击后光标仍停留在第 4 行。

安装包版本提升到 `3.1.52.15`，使已安装 3.1.52.14 的用户可以正常升级。测试发布使用 `v3.1.52.15-preview.2` 标签；稳定版 3.1.52.13 保持不变。
